# 增长产品每周观察编辑检查表

## 选题判断

- 这个产品卖的是什么？
- 用户在什么具体场景下付费？
- 过去一个月的增长信号是否来自支付相关行为？
- 是否适合一人公司借鉴？
- 是否存在合规、平台规则或公共推荐风险？

## 证据层级

优先级从高到低：

1. 官网首页、Pricing、Docs、FAQ、About。
2. 页面 metadata、H1/H2/H3。
3. Product Hunt、Reddit、X、Trustpilot、目录站、媒体报道。
4. Similarweb/数据库指标。

不要只凭域名、页面外观或商品缩略图判断用途。

## 好描述

- “把课程和会员资料交付成一个品牌 App”
- “判断某个关键词到底能不能排上去”
- “把一个商品链接变成可上线 Shopify 店”
- “用实体设备限制刷手机”

## 差描述

- “AI 提效工具”
- “创作者平台”
- “小众商品站”
- “页面看起来像某种订购入口”
- “用硬件触发专注阻断”

## 必删风险

- 加密交易、交易信号、自动交易。
- 受管制商品或地区违法商品。
- 赌博、成人、仿冒、账号黑产、明显规避平台规则。
- 需要不确定语气才能解释的产品。

## 公众号文案

- 直接写事实和判断。
- 避免“不是 X，而是 Y”。
- 不写数据来源 target domain。
- 不把内部分析过程暴露给读者。

## Markdown 输出检查

- Frontmatter 字段完整：title、description、pubDate、tags、draft。
- 封面信息包含 WEEK 编号、产品数量、署名。
- 产品编号连续，从 1 开始。
- 每个产品包含：产品名、截图、domain、上线时间、推荐指数、thesis、四个板块。
- 截图路径指向 `public/images/weekly/{week}/`，文件名用域名 slug。
- 付款行为数字模糊化，不展示精确值。
- 不使用 HTML 标签，纯 Markdown 语法。
- 产品之间使用 `---` 分隔。
- 结尾有完整标记和署名。
- 图片是真实首页截图，不是卡片或占位图。
- 没有数据源内部词泄露：不含 Similarweb、TrustMRR、Semrush、RDAP、WHOIS、SQLite、缓存、快照、raw、target、referral、抓取失败、403 等。
- 没有内部状态词：不含 not_found、unknown、checked_no_hit。
- 付费可读版本把封面目录（产品概览列表）放在全文最后。
- 全文连续可读，适合在 jinzheio 和公众号两端发布。
